## 结论（先看这里）

1. **配置面达成**：现有配置项 `MORAY_CHUNK_MAX_UNITS=3500` 可设；`overlap_units`
   默认 200 与行为完全不变，有配置级测试锁定。**默认值仍为 1500，本单没有切换**。
2. **运行面达成**：单文档调用数 26 → 9（**−65.38%**，方向与离线探针 −57% 一致），
   输入 token −43.64%、输出 token −26.70%、端到端墙钟 −7.36%；压力语料与 11 篇
   真实文档的截断块均为 **0**；真实 tokenizer 口径下最大块“正文+系统提示+schema”
   仅 **3,836 input tokens**，距 1,048,576 上下文上限余量 **1,039,338 tokens（99.12%）**。
3. **准确率门槛未通过**：1500 → 3500 的实体 macro-F1 为 **−4.35pt（mean）/ −4.30pt
   （worst）**，超过 ≤0.5pt 门槛；关系 F1 为 **−7.48pt（mean）/ −2.50pt（worst）**，
   属于下降。按协调者规则：**任一门槛不过就不切换默认值**，因此默认保持 1500，
   本单**未添加**默认值切换 commit。验收第 2 条如实标为“未通过（不切换）”。
4. **失败原因已定位为评测口径的 FP 膨胀，不是 3500 把已认可答案抽丢**：
   TP 基本不变（实体 691→686、关系 822→810），FP 大幅增加（实体 32→104、
   关系 755→925）。增量 FP 主要来自工单 02 语料**刻意未写进 gold 的句面**
   （每篇 18 句“法定代表人{PER}”、卷四每案 5 名涉案人只标 1 条等）。3500 档
   上下文更完整，模型把这些真实存在但不在答案里的内容也读了出来，被记 FP。
   这正是 `evaluation/stress/corpus.py` 文件头已写明的 gold 子集限制；本单
   遵守“不许改语料/匹配逻辑让 A/B 过关”，原样列报。

## 为什么准确率门槛没过（逐项对账，不掩盖）

| 计数（3 篇 × 3 轮） | 1500 | 3500 | 变化 |
|---|---:|---:|---:|
| 实体 TP | 691 | 686 | −5 |
| 实体 FP | 32 | 104 | **+72** |
| 实体 FN | 122 | 127 | +5 |
| 实体 recall | 0.8500 | 0.8439 | −0.61pt |
| 关系 TP | 822 | 810 | −12 |
| 关系 FP | 755 | 925 | **+170** |
| 关系 FN | 204 | 216 | +12 |
| 关系 recall | 0.8012 | 0.7895 | −1.17pt |

- 实体 FP 增量拆开：EVENT +72（上述 `案件编号 ` 前缀）、PER +12、ORG −12；
  TP/FN 几乎不动，**不是把金标实体抽丢了**，而是把“正文里真实出现、但 gold
  故意未收”的人名/机构名多抽了出来。
- 关系 FP 增量主要来自 `涉案关联`。单篇诊断（`stress_seed20261102`）：
  1500 档预测 `涉案关联` 4 条、3500 档 76 条；两档 TP 都是 90、FN 都是 24，
  F1 0.7792 → 0.5941 的跌幅**全部由 FP 造成**。这些句面正是 02 语料
  “卷四每案列 5 名涉案人、只记第 1 条”的刻意设计。
- 02 语料的 `gold_scope_note` 已写明：注入真实 LLM 做 A/B 时，这些句面会被
  记 FP，绝对 P 会被低估；A/B 只应比较同一被评对象的增量。本报告保留这个
  限制，不为了让门槛过关去改语料、改匹配或换指标。

## 真实 tokenizer 上下文余量（不是 estimate_tokens）

`usage.input_tokens` 是 provider 对**完整请求**的真实计数，已经包含
正文 + 系统提示 + 结构化 schema；`max_chunk_input_tokens` 取压力语料与真实
文档两批的最大值（单块多次尝试时取和，属保守上界）。

| 口径 | 1500 | 3500 |
|---|---:|---:|
| 最大单块 input tokens（真实 tokenizer） | 2,523 | **3,836** |
| 最大单块 output tokens | 5,482 | 5,402 |
| 模型 context_window | 1,048,576 | 1,048,576 |
| input 余量（tokens / %） | 1,046,053 / 99.76% | **1,044,740 / 99.63%** |
| input+output 余量（tokens / %） | 1,040,571 / 99.24% | **1,039,338 / 99.12%** |
| 模型 max_output_tokens | 393,216 | 393,216 |
| output 上限余量 | 387,734 | 387,814 |

- 结论：3500 档即使把系统提示、schema、正文全算进去，也只占上下文的 0.37%，
  距上限还有 **1,039,338 tokens（99.12%）** 的安全余量；输出侧余量
  387,814 tokens，且实测截断 0。
- 切块估算单位与实际 token 不是同一口径：最大块估算 3,597 units（overlap
  可让块超过 `max_units` 至多一个 overlap，这是改造前就有的语义），真实
  tokenizer 计数 3,836；报告里两者分开标注，没有拿估算器冒充真实值。

## overlap 不变的证明

- 两档配置值都是 `overlap_units=200`；本单没有改 `chunking.py`、
  没有改 `chunk_settings()` 里 overlap 的默认值。
- 实际行为：相邻块“后块起点早于前块终点”的重叠对数，两档最小值分别为
  8（1500）和 7（3500），都 >0；overlap 仍然生效。
- 配置级测试：`tests/test_chunk_budget.py` 锁定默认 1500/200、设置 3500 后
  overlap 仍是 200，并断言 3500 档相邻块仍存在重叠文本；`tests/test_chunking.py`
  的既有 overlap 用例继续通过。

## 残余文档级跨块关系（显式统计，不算本单回归）

口径：对每条 gold 关系，只要**存在一对头/尾出现落在同一个块内**，就算该预算
可覆盖；否则算跨块残余。残余逐条列在 JSON 的
`residual_cross_chunk.<budget>.residual_relations`。

| 预算 | 可同块 | 跨块残余 | 残余比例 |
|---|---:|---:|---:|
| 1500 | 338 / 342 | 4 | 1.1696% |
| 3500 | 342 / 342 | 0 | **0.0000%** |

另外单列“文档级远距首现”类别：头尾**首次出现**间隔超过一个块预算的关系，
两档都是 **60 / 342 = 17.5439%**；典型间隔 14,361–25,044 units（例如
`徐永刚 → 断线钳` 25,044 units、`杨俊杰 → 断线钳` 24,911 units）。这类关系
靠“卷尾重复点名”才能被同块覆盖——3500 档 342 条全部覆盖，1500 档仍有 4 条
落在跨块。它们是**调大块预算也无法从文档结构上救回**的类别，本单不处理、
不计作回归、也不静默丢弃；JSON 中 20 条样本逐条带
`covered_by_repeated_mention` 标记。

> 工单描述里的“约 7%”来自另一次 1.8 万字压力案卷的离线探针，不是本 02 语料
> 的直接复现；本报告只报本次实测的 0% / 1.17% 与 17.54% 两个口径，不冒充 7%。

## 默认值切换：本单未执行

当前代码默认值仍是 `chunk_settings()` 的 `max_units=1500`、`overlap_units=200`。
按协调者规则，准确率门槛未过就**不加**切换 commit；线上行为不变。

若后续用更合适的评测口径重新达标，切换动作是单独一个 commit、只改
`src/moray/config.py::chunk_settings()` 里 `MORAY_CHUNK_MAX_UNITS` 的默认值
`1500 → 3500`（overlap 不动），回滚直接 `git revert <该 commit>`；也可以不改
代码、只在部署环境设 `MORAY_CHUNK_MAX_UNITS=3500`，删掉该 env 即回滚。

## 需要 owner 决策的下一步（不在本单改）

要让 3500 真正可切换，必须先解决“02 语料 gold 是刻意子集”这一评测口径问题，而不是
继续调块预算：

2. 或由 owner 明确 **预算 A/B 的关系判据改用“金标覆盖子集/召回”**，并写进门槛；
3. 另可单独修模型把 `案件编号 A2024-xxx` 写成实体名的口径（影响 EVENT P/R，
   与本单切块无关）。

在这三项任一落地前，生产保持 1500；本单不擅自改语料、匹配逻辑或默认值。
